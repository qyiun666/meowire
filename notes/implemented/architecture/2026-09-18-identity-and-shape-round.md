# 决策档案: 身份必须声明，形状轮只碰内核自有的形状

Status: implemented

## Problem

一次以「仿生 harness 内核」为对象的审查，抓出的东西分两类。

一类是**身份**：装配面允许 agent 不命名，用一个所有实例都会分到的默认名；而多 agent 的文档路子正是一份装配复用多次。于是那条「挂起句柄不得被兄弟实例恢复」的守卫，在默认路径上按名字判定、按定义失效——它拒绝的是「另一个名字」，而兄弟们的名字相同。同一类里还有第二处：关闭后的拒绝在两条路径上产出两个不同的错误值，宿主按文档承诺的身份判定去匹配，在其中一条上必然落空。

另一类是**形状**。这个内核在裁决、挂起、审计三条线上追平或超过了当时的生态，落后的部分全部集中在「端口之间流的字节长什么样」：一条被落盘的事件流说不出自己的顺序，一份日志里混着几个 agent 时无从判断「它没话说」还是「记录丢了」；而挂起应答这套协议本身是内核发明的，却用宿主自由文本的前缀来判批准——一句恰好以那个前缀开头的回答会被静默判否。

同时被重新提出的还有一件旧事：既然宿主接一个模型要自己写完 Thinker，要不要干脆内置一个（这一回是引第三方 LLM SDK，而不是自己手写），并且围绕它把那个端口从必填里去掉，让「开箱即用」成为仿生内核的卖点。

## Decision

身份不留默认。**一个 agent 必须自己报名**：装配期把 unnamed 判为 error 级发现，与「缺席器官即装配错误」用同一把尺子。跨进程恢复的句柄要能在重启后被同一个身份认领，所以身份只能是宿主持有的那个名字，不能是每次装配现生的随机数——用后者换守卫会把「挂起轮活过进程重启」这项能力赔进去。实例之间的重不重名是宿主的声明，内核看不见自己的兄弟，就不替它编一个名字。关闭后的拒绝收敛为单一判据：一份关闭标志、一个哨兵值、经门面再导出，并进入事件线的按名还原表。

形状轮划一条边界：**只改内核自己拥有的数据形状，不引进任何 provider 词汇**。事件因此带上序号与发出时刻，与署名同一个盖章点、同一条理由（这些事实属于边界，不属于循环里某处的产出者），线格式随之升版，旧版本日志宁可拒读也不猜。挂起应答不再是一套字符串语法：`Resume` 收 `Response{Answer, Deny}`，四种成因共用，读哪个字段由 `Session.Kind()` 点名——成因早就随句柄走线（按名编码、有版本闸门），本轮只是把它变成读得出的。拒绝从此有它自己的去处：工具等待的拒绝落进 `ToolResults.Err`（那是一次调用失败），膜的征询落进 `[sandbox-denied: reason]`（那是一条裁决），两者不再挤在同一格文本里。前缀协议净删除，不留兼容分支：一个以内核前缀开头的答复就是一段答复。

内置 LLM 客户端这条维持否决，并把否决理由与「一个端口变可选」的结构后果一起写进仓库的「明确不做」，因为它已经不是第一次被提出。

## Alternatives considered

- **内置 openai-go/v3 并去掉 Thinker 端口**（本次提出）—— 落选，三条理由：① 卖点反转。这个内核区别于同类的那一句是「内核只有神经与接线，器官归宿主」，而这句话能被测试机械验证；自带一颗脑之后它变成「又一个 SDK 封装 + 一条循环」，正面撞进以模型绑定为主卖点的竞品地盘，丢掉唯一差异。② 「去掉一个端口」在结构上等价于「这个端口可以缺省」，而本仓的地基是「每个接线点必填、缺席即错误」；有了第一个默认器官，第二个只是时间问题。③ 引第三方包把发布节奏挂到别人的 release 上，比上一次同类尝试（stdlib 手写）代价严格更高。
- **保留默认名，只在文档里警告宿主「多实例请各自命名」** —— 落选。警告不改变「默认路径上守卫失效」这一事实，且这个默认名当时正被文档当作推荐用法写进示例。
- **每次装配生成一个实例内 nonce，由句柄携带** —— 落选。进程重启后 nonce 必然变化，跨重启恢复挂起轮直接报废：用破坏旗舰功能换一条守卫。
- **在门面加 provider 中立的 canonical 消息/内容块轨** —— 落选（本轮）。它与上一节「内核不携带器官实现」的判据正面冲突：那次裁定专门删掉过「只为渲染器存在」的槽位。渲染确实是宿主每个 provider 要重写的东西，但它属于器官的选择，不属于接线层；要重开就得先推翻那条裁定，而不是顺手加一枚字段。
- **事件流加 token 级增量** —— 落选，且理由与上面不同：不是归属问题而是结构互斥。出口膜裁决的单位是「一整轮的文本」，流式化必须重定义裁决粒度，做了会削弱本仓真正领先的那一项。要动它得先有一篇把它当主角的档案。
- **`ToolSpec.Input` 换成结构化 JSON 类型、`Effect` 加结构化输出字段** —— 落选。这两个字段的流向是宿主→内核→宿主，内核只做透传与截断，从不解释其内容；换类型不让端口契约更好装配，按本仓的评价函数不成立。
- **本轮只在 `Validate` 加一条 info 判词点名前缀撞车，把类型化推到下一轮** —— 落选（计划里作为退路列出）。实测改动面比预估小一个量级（生产代码三处判词 + 一次签名传递，测试面 13 个调用点），而退路是把一个「静默改判宿主输入」的缺陷留成已知敞口：它不修问题，只是把问题登记下来。
- **把成因作为 `WaitInput.Kind` 字段挂在事件上，同时进事件线** —— 落选。同一事实会有两个来源（事件字段与句柄内已按名编码的成因），跨进程还原时二者可以不一致，而线格式没有能力裁定该信谁；句柄本身就是这条事实的权威载体，`Session.RemainingCalls()` 已经开过「只读探测」这个先例。
- **把本轮所有破坏性项摊成多个 tag** —— 落选。契约变更只经 tag 生效，宿主每跟一次版都要改一轮代码；同属「身份与形状」的破坏面并一批。

## Consequences

- 宿主侧有一处必改：每个实例要自己报名。示例、两份集成指南与参考宿主同时改口，测试的装配 helper 补上名字。
- 一份按旧线格式写的日志在新 build 上读不回来。换来的是落盘的事件流自证顺序与时刻；宿主若已 journaling，要么留旧 build 读旧日志，要么迁移。
- 「不内置器官」这条从一句意图陈述变成了带后果的条款：以后想降门槛，先回答「端口必填这条纪律还要不要」，而不是先写一个默认实现。
- 宿主侧第二处必改：`Resume` 的第三个实参从字符串换成 `Response`。原先靠传 `"[denied: ...]"` 表达拒绝的写法要改成 `Response{Deny: 原因}`，且**它的语义也变了**——同一个拒绝在工具等待上不再是模型读到的结果文本，而是那次调用的失败。
- 判定「仿生是否只是修辞」的结论落在三处承重结构上（细胞署名、双侧膜、四种成因共用一枚挂起句柄），本轮没有为隐喻新增任何机制；缺失的生物机制里只有「在途抑制」存在不加端口就能落地的路径（把宿主对 ctx 的取消映射成一次可恢复挂起而非错误终态），已登记为候选，未实施。
