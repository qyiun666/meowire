# 决策档案: 内核不携带器官实现 —— 纯度判据与它的接线闭合

Status: implemented

## Problem

一个 LLM 客户端要同时回答两件与本仓无关的问题：协议怎么传（SSE 帧、双 wire 差异、重试退避）和文案怎么排（Prompt 各槽位渲染成什么）。这两件事都随外部服务商变化，而内核的承重契约是端口形状与事件语义。把它们放在同一个 module 里，读者无法判断哪些是「接线层的规定」、哪些是「一个可选器官的样例」，`Thinker` 端口也因此在文档里被写成了「有官方实现可用」——端口收敛 pressure 由此产生。

## Decision

内核只携带接线：一个 agent 的神经元（决策循环与七个端口）与器官壳（契约与调用时点）。
任何器官的具体实现——LLM 传输、Prompt 渲染、工具执行、记忆后端——都不进本仓；
**agent 之间的连接也不进本仓**：寻址、投递、回程配对、能力发现、突触权重与学习规则
全在宿主。

判据落成一句可检验的话：**宿主只实现器官，不需要补任何接线代码，就能装配出可用的内核**。
一个 agent 要问另一个 agent，就在宿主的工具里 `New` 出那个实例、消费它的事件流——「谁可以
被谁问到」这张表属于宿主的世界观，内核连声明它的那一面都不持有，`Organs` 上不允许出现
面向邻居的槽。做不到这一点的位置算作接线缺口，由内核补齐；能做到的位置即使不方便，也属于
宿主的器官选择，内核不代劳。

判据由两份测试机械守住：`test/public_organs_test.go`（器官全部用公开名写出，一次 `Stimulate`
跑完两轮）与 `test/wiring_free_test.go`（扫描宿主侧文件里是否出现 channel / goroutine / 队列
接收，以及 `Organs` 字段集合是否多出一项）。补齐过程中确立的界线，比判据本身更难重新推导：

- **一次调用的终态由循环给出，不由器官自觉给出**：`OnCycleEnd` 的 `CycleOutcome` 是这次运行
  如何结束的唯一判词；宿主拿它映射自己的任务状态，框架不代为宣布任何协议级状态。
- **配对与续跑是两件事，两件事都不归框架**：一个 agent 的答复何时成为另一个 agent 的下一步，
  是宿主的调度权；框架连「替宿主 Resume 一次」都不做。
- **审计记录只描述，不持有**：端口替换的记录晚于替换本身才产出，若它持有活的端口，就既让
  退休器官续命，又让自己不可序列化。

## Alternatives considered

- **保留 `openai/` 作为官方示例器官** —— 落选。示例的价值在于示范端口形状，而宿主视角的示范已由 `reference-host.md` 与 `host-integration.md` 的骨架承担；一份可 import 的实现带来的不是示范，是「应当用它」的暗示。
- **移到 `examples/` 独立目录** —— 落选。它仍需编译、随协议演进入测试面，维护成本一分不减，只是把归属问题推迟。
- **降级为 internal 测试替身** —— 落选。测试要的是可控假实现，不是真协议镜像。
- **维持现状等第二个宿主出现再收** —— 落选。判据不依赖宿主数量：外部协议知识本身就是业务侧内容。
- **只删集群机器、保留一个「投递器官」壳（`Colony.Fire` + 信号信封 + 回程配对）** —— 落选（同一次裁定里被推翻）。它把「一个进程只 `New` 一个 meowire，多个 meowire 彼此独立」这条判据写成了例外：只要信封还在，`Organs`、`Prompt`、`Session`、事件线就都得替「邻居」留位置，名实不符会一直复发。
- **只改文档措辞、代码原样留着** —— 落选。说过头的那两句（「组出多 agent 内核」「零宿主管道」）确实可以改准，但改措辞不改变公开面上有几百行面向邻居的事实，下一轮还会被同一问题重开。
- **让宿主自己序列化事件** —— 落选。默认编码会把 error 字段写成空对象、把枚举写成编号，而且什么都不报告；跨进程重放缺的不是一个函数，是「这个形状归谁」的归属。

## Consequences

- 事件流有了框架自有的可持久形状，代价是一份新的版本义务：事件字段变动必须同时被线格式与覆盖守卫接住，版本与枚举名字不符即拒读，宁可拒绝一份旧日志也不猜。
- 审计记录不再携带活的端口值——本轮唯一的破坏性变更。宿主想拿回被换下的器官，本来就有那条返回值；换来的是事件流整体可落盘。
- 集成成本回到宿主侧：接一个新模型必须自带 Thinker；一个 agent 要问另一个 agent，宿主自己接线。已核实的代价为零——宿主 meowagent 全程使用自家实现，从未 import 过该包，删除不影响任何下游。
- 内核换取可检验的纯度判据，代价是它必须补齐原先被示例掩盖的接线缺口：入站事件的署名、预算的完整覆盖、事件线的读写两侧把关，都成了内核的责任而不是「宿主照着示例自己接」的余地。
- 一次跨实例的往返不再有任何框架代码参与：内核少掉一整个连接层包与它那份可选器官，`Session` 快照随之不再携带未答请求账本。
- 文档四处曾把内置实现写成当下事实（README 双语、两份 host-integration、AGENTS 意图段），随本决定改写；`Prompt.State` 这一类「只为渲染器存在」的槽位一并出局，进脑数据包由此变干净。
