# 决策档案: 内核不携带器官实现 —— 纯度判据与它的接线闭合

Status: implemented

## Problem

一个 LLM 客户端要同时回答两件与本仓无关的问题：协议怎么传（SSE 帧、双 wire 差异、重试退避）和文案怎么排（Prompt 各槽位渲染成什么）。这两件事都随外部服务商变化，而内核的承重契约是端口形状与事件语义。把它们放在同一个 module 里，读者无法判断哪些是「接线层的规定」、哪些是「一个可选器官的样例」，`Thinker` 端口也因此在文档里被写成了「有官方实现可用」——端口收敛 pressure 由此产生。

## Decision

内核只携带接线：神经元（决策循环与端口）、突触（连接与状态存储）、器官壳（契约与调用时点）。任何器官的具体实现——LLM 传输、Prompt 渲染、工具执行、记忆后端——都不进本仓。

判据落成一句可检验的话：**宿主只实现器官，不需要补任何接线代码，就能装配出可用的内核**。声明拓扑——哪些 agent 之间存在一条边——不算补接线代码，那是宿主的世界观；它说错了也不静默：答复在发不出去的那一侧被报出来（见 `test/colony_test.go` 的单向边用例）。做不到这一点的位置算作接线缺口，由内核补齐；能做到的位置即使不方便，也属于宿主的器官选择，内核不代劳。

判据如今由一次多 agent 往返的集成测试机械守住（委托 → 投递 → 作答 → 配对全程无宿主接线代码）。补齐过程中确立的四条界线，比判据本身更难重新推导：

- **委托是返回值，不是宿主手里的句柄**：一个 cell 要问邻居，工具只需说出「问谁、问什么」，铸号、盖状态、投递、配对都归内核。宿主一旦持有句柄，编号与配对就会被各写一遍。
- **作答挂在调用的终点上**，不挂在某个器官的自觉上：一次调用结束时它服务过的请求恰好取得一个终态，六个任务状态因此各有唯一写入者。
- **配对归内核，续跑归宿主**：内核能判断这条回复属于哪一轮，但「这一轮现在能不能继续」是宿主的调度权，框架代为续跑就越界。
- **审计记录只描述，不持有**：端口替换的记录晚于替换本身才产出，若它持有活的端口，就既让退休器官续命，又让自己不可序列化。

事件流的出口同理：流要能离开进程，就必须有一个框架拥有的形状，而不是让宿主去序列化内部结构体——后者会静默丢掉错误文本、把枚举写成数字。框架因此给出带版本的事件编码，并把「过不去的值」在事件上点名，而不是丢了就当作没发生。

## Alternatives considered

- **保留 `openai/` 作为官方示例器官** —— 落选。示例的价值在于示范端口形状，而宿主视角的示范已由 `reference-host.md` 与 `host-integration.md` 的骨架承担；一份可 import 的实现带来的不是示范，是「应当用它」的暗示。
- **移到 `examples/` 独立目录** —— 落选。它仍需编译、随协议演进入测试面，维护成本一分不减，只是把归属问题推迟。
- **降级为 internal 测试替身** —— 落选。测试要的是可控假实现，不是真协议镜像。
- **维持现状等第二个宿主出现再收** —— 落选。判据不依赖宿主数量：外部协议知识本身就是业务侧内容。
- **让宿主自己序列化事件** —— 落选。默认编码会把 error 字段写成空对象、把枚举写成编号，而且什么都不报告；跨进程重放缺的不是一个函数，是「这个形状归谁」的归属。

## Consequences

- 事件流有了框架自有的可持久形状，代价是一份新的版本义务：事件字段变动必须同时被线格式与覆盖守卫接住，版本与枚举名字不符即拒读，宁可拒绝一份旧日志也不猜。
- 审计记录不再携带活的端口值——本轮唯一的破坏性变更。宿主想拿回被换下的器官，本来就有那条返回值；换来的是事件流整体可落盘。
- 集成成本回到宿主侧：接一个新模型必须自带 Thinker。已核实的代价为零——宿主 meowagent 全程使用自家实现，从未 import 过该包，删除不影响任何下游。
- 内核换取可检验的纯度判据，代价是它必须补齐原先被示例掩盖的接线缺口：神经元接收器、突触传导、预算的完整覆盖，都成了内核的责任而不是「宿主照着示例自己接」的余地。
- 文档四处曾把内置实现写成当下事实（README 双语、两份 host-integration、AGENTS 意图段），随本决定改写；`Prompt.State` 这一类「只为渲染器存在」的槽位一并出局，进脑数据包由此变干净。
