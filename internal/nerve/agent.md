# MeowAgent nerve module context (capability layer: decision loop + ports)

> Package lives at internal/nerve — sealed from external import; hosts use only the api package API.

## Purpose

- Capability layer: decision loop orchestration, host ports (Thinker/Effector/Closer), hooks, events
- File layout by concern: `state.go` (loop states, round cap, LoopConfig), `invocation.go` (LoopContext — the one data package an invocation runs on), `loop.go` (Cycle/Resume, round loop, Think), `inbox.go` (the round's inbound track: ingest, the answer-at-terminal step, notice withholding), `correlation.go` (Correlation — a delegation the kernel tracks), `task.go` (the single CycleOutcome → TaskStatus mapping), `feedback.go` (actBatch — one round's Act path, incl. delegation), `gate.go` (membrane ruling, audit, denial), `pause.go` (pause gate + the shared suspension snapshot), `retry.go` (Think/Act retry, truncation), `parallel.go` (opt-in batch path), `hooks.go` (hook adapters + error terminal), `budget.go` (where the regulator is applied), plus `port.go`, `memory.go`, `event.go`, `signal.go`, `wire.go`, `compose.go` (organ combinators: many implementations behind the one port the loop sees), `lifecycle.go` (the optional `Bootable` capability + `PortOrder()` read off the blueprint), `eventwire.go` (the event stream's portable shape: versioned records, enums by name, and the `Dropped` accounting for what a wire cannot carry), `names.go` (the two generic readers every enum name table goes through, so no table can drift into guessing on an out-of-range value)
- `size_test.go` enforces the complexity budget mechanically (file ≤400 lines, function body ≤50, ≤4 params) over the whole module; the exemption list is closed and each entry carries its reason
- Guard ports: Sandbox (execution boundary + text egress), ContextBudget (context size limit), Memory (when experience is recalled and written back)
- Depends on nothing above cell/synapse/root

## Dependencies

- Go standard library only (zero third-party dependencies)

## Interface Contract

- `DecisionLoop{}.Cycle(ctx, *LoopContext, yield)`: pure orchestration — Think → Act → yield events
- `DecisionLoop{}.Resume(ctx, *LoopContext, sess Session, response string, yield)`: continues a suspended loop from a Session (EventWaitInput or EventPaused) — for a tool suspension the response is injected as the pending tool's structured result (pending.ID == "" for pause suspensions: nothing is injected, the loop just continues); a membrane ask suspension (sess.kind waitCallAsk / waitUtterance, wire v3) resolves on the same channel — an empty or `[denied:`-prefixed response denies the pending call (`""` defaults to the `[sandbox-denied: declined]` feedback, a `[denied:`-prefixed response denies with its text in the canonical `[sandbox-denied: ...]` form — input protocol and output feedback are distinct formats), any other response approves: the pending call runs without re-gating (non-pending siblings still pass the normal gate on replay), a withheld utterance is said as generated with no second Think; remaining tools run, round loop resumes from the suspended round (no extra round, no budget during the wait); stream/hooks/guarantees isomorphic with Cycle
- `LoopState`: StateIdle/StateThinking/StateActing/StatePaused/StateWaiting/StateDone/StateError (StatePaused + EventPaused yielded by the pause gate at gap points, iterator ends normally — resumed via Resume(sess, ""); StateWaiting + EventWaitInput yielded when a tool suspends — resumed via Resume(sess, response))
- `LoopConfig{MaxRounds, MaxToolOutput, MaxRetries, ToolTimeout, ToolMaxRetries, ParallelActs, MaxParallelActs}`: scalar loop config (single source; api.Config aliases it); UpdateConfig swaps it wholesale — next Stimulate/Resume snapshots the new values; MaxParallelActs (<=0 = none) caps how many calls of one parallel batch execute at once and binds nothing while ParallelActs is off
- `LoopContext{CellID, Identity string, Methods []MethodSpec, Think, Act, Hooks, Sandbox, Budget, Mem, Pause, Ingest, Send, Await, MaxRounds, MaxToolOutput, MaxRetries, ToolTimeout, ToolMaxRetries, ParallelActs, MaxParallelActs, State, Input, Plan, Context, Bounds, Reflection, ToolResults, Memories, Stimuli, Requests, PendingReplace, PendingConfig, System, Tools}`: all ports injected via fields; `Reflection` is the turn-scoped self-review note carried onto every Thinker prompt (written back from the BeforeStimulate prototype); `Memories` is the round's recall output and `Stimuli` the round's inbound track (both volatile: replaced before every Think, never accumulated, never snapshotted into a Session); `Requests` is the answer debt — peer requests this invocation is serving, accumulating across rounds and surviving a suspension through the Session; `Ingest`/`Send`/`Await` are framework wiring like `Pause`, not host ports, and the loop never handles a channel itself (all three nil = no colony wiring)
- `PauseGate{IsPaused}`: optional pause gate (nil = unsupported); the loop checks it at gap points (before each Think, before each tool execution) — a pending pause yields EventState(StatePaused) + EventPaused with a Session snapshot and ends the iterator normally (unified suspension-resume path; no blocking, no ResumeCh)
- `Prompt{System, Identity string, Methods []MethodSpec, Tools, Context, Bounds, Input, Plan, Reflection, ToolResults, Memories, Stimuli, Inhibit}`: sole data package delivered to Thinker; Reflection = turn-scoped self-review note (write it on the BeforeStimulate prototype; empty = absent); Context = host-injected base + framework-appended refusals (`[sandbox-denied: ...]` from the membrane, `[inhibited: ...]` from a notice — both appended in final form by `actBatch.refuse`) — the text track holds only those two, and a refused call therefore never appears on the structured track; Bounds = Sandbox.Bounds() snapshot taken once per Stimulate; ToolResults = single structured track (ToolResult{ID, Name, Result, Err} — ID echoes the LLM call id, Result/Err carry the truncated raw output, Err non-empty = failed; not trimmed; sandbox denials never appear; rendering is the host's decision); Stimuli = the signals this cell's inbox held at the Think gap (volatile like Memories — how a host interprets them is the host's, the loop only delivers them); Inhibit = tool names this round's `KindNotice` signals withdraw (a matching call is refused before the gate sees it; never revoked once in flight)
- `Decision{Text, ToolCalls, Usage}`: Thinker output; non-empty ToolCalls triggers Act phase; Usage (nil = skip) is yielded as EventUsage
- `Action{CellID, Call}` / `Effect{Result, Err, WaitInput, Send}`: tool execution pair; WaitInput non-empty = suspend the loop (request external input; the field is the question text) — the loop yields EventWaitInput and ends the iterator normally, the host resumes via Resume(sess, response); WaitInput wins over err (explicit intent), a nil effect never suspends; `Send *Signal` = delegate the call to another cell and wait for its answer (the host names `To`, the cell stamps `ID`/`From`/`Kind`/`Status` and delivers through its Colony organ) — a delivered send suspends through the same path with `WaitInput = "awaiting reply from <to>"`, an undeliverable one (no target named — `Skill` is a capability, not an address; no Colony organ; unknown or busy target; or a wait that arrives after the round's single suspension is spent — another Send, or a sibling call's own `WaitInput`, refused by `refuseLaterWait`, whose text appends after any `Err` the tool already reported rather than replacing it) becomes that call's tool feedback like any other resistance and never suspends; `WaitInput` wins over `Send` (a call carrying both keeps its own question and its delegation is not delivered)
- `WaitInput{CellID, Call, Question, Session}`: EventWaitInput/EventPaused payload — the suspending tool (Call zero value for a pause or an utterance ask), the question text (empty for a pause), and the resume handle
- `Session` (opaque): snapshot at the suspension point (round/input/plan/context/output/pending/remaining/toolResults — all unexported); produced by the framework, consumed by Resume; hosts only save and pass it back; single-use (resuming twice re-executes remaining tools — host responsibility); valid iff round >= 1 (zero value rejected); `Session.cell` is stamped by the framework at snapshot time; `RemainingCalls() []ToolCall` is the sole sanctioned read-only probe — a clone of the calls not yet executed at the suspension point (empty when nothing is left to run); persistence round-trip via `Marshal() ([]byte, error)` / `UnmarshalSession([]byte) (Session, error)` (JSON wire shape with version guard — a stale or future handle is rejected; wire v3 carries the owning `cell` (Resume rejects a foreign handle with `ErrForeignSession`), the name-encoded `waitKind` (pause/tool/call-ask/utterance-ask), the withheld `utterance` draft and the unanswered peer `requests`)
- `Identity string`: identity description text, host composed (no structure enforced)
- `MethodSpec{Name, Desc, Input, Output}`: built-in capability description (gene projection, describes only)
- `ToolSpec{Name, Desc, Input, Output}`: host-defined tool specification
- `Usage{Prompt, Completion, Total}`: token accounting; host accumulates via EventUsage events
- `Event{CellID, Kind, Text, ToolCall, Effect, State, Err, Output, Usage, Verdict, Wait, Replace, Config, Dropped}`: typed event from each loop iteration; `CellID` is stamped by the cell on every event at its boundary (who spoke is the cell's fact, not each producer's), and `Dropped` is written by no producer at all — only `DecodeEvent`, naming the values that arrived as shadows
- `EventKind`: EventText/EventToolCall/EventToolResult/EventState/EventDone/EventError/EventUsage/EventSandbox/EventWaitInput/EventPaused/EventReplace/EventConfig (`String()` gives each one's wire name from one table indexed by value, so a kind added to the iota without a name is reported `unknown` and refused rather than reinterpreted)
- `ReplaceAudit{CellID, Slot, OldType, NewType}`: audit record carried by EventReplace — one per successful Replace, emitted at the start of the next Stimulate/Resume (the moment the swap takes effect), before any other event; failed swaps record nothing. The swapped ports are named by Go type, not held: the record outlives the swap and is journalled, so a live value inside it would keep a retired organ alive and unserializable (the host that wants the displaced organ gets it from `Replace`'s return value)
- `ConfigAudit{CellID, Old LoopConfig, New LoopConfig}`: audit record carried by EventConfig — one per successful UpdateConfig, emitted at the start of the next Stimulate/Resume after EventReplace (the moment the swap takes effect); the config-update counterpart of EventReplace (every "unique update" of the loop is traceable)
- `EncodeEvent(Event) ([]byte, error)` / `DecodeEvent([]byte) (Event, error)` and the wire shape `WireEvent{Version, Kind, ...}` + `WireErr{Code, Text}` / `WireVerdict` / `WireWait` (eventwire.go, `eventVersion = 1`): the event stream's portable form for a host that journals events or replays them in another process. Decode fails loudly on malformed JSON, a foreign version, an unknown kind/state/ruling name, or a `Session` whose own version guard rejects it (the handle stays inside the record as its own bytes, so the event wire cannot grow laxer than the handle it carries). The write side holds the same line — `EncodeEvent` refuses a ruling with no name and a state name carried on a non-state kind — because a record nothing can read back is a poison entry in the journal, not a lost detail. What cannot be carried is still carried, and named: a framework sentinel (`max-rounds`, `foreign-session`) returns as the identical value — wrapped in `wrappedErr` when it arrived wrapped, so both `errors.Is` and the sender's text survive — while any other error comes back as fresh text and the event adds `err.identity` / `verdict.err.identity` to `Dropped`. A bare `json.Marshal` of an Event is not this: it writes an `error` field as `{}` and loses the text without saying so
- `Verdict`: tri-state sandbox ruling — VerdictDeny (zero value, fail-closed) / VerdictAllow / VerdictAsk. A value outside that table has no name, so it is not a ruling this build understands: `knownRuling` (gate.go) coerces it to Deny at every entry point — both membrane sides and `guardStack.rule` — instead of letting a `switch` default branch execute the call
- `SandboxVerdict{CellID string, Call ToolCall, Ruling Verdict, Reason string, Question string, Err error}`: audit record carried by EventSandbox — one record per ruling on either side of the loop (the membrane is required, so nothing is unaudited): `Call` names the gated tool, a zero `Call` is the utterance side; an ask ruling produces two records on one chain (ask → resolve; the terminal record closes it with the final Ruling/Reason — deny keeps the deny text, approval shows Ruling allow with empty Reason)
- `CycleOutcome`: zero-value-reserved classification of how the cycle ended — OutcomeDone / OutcomeSuspended / OutcomeMaxRounds / OutcomeError / OutcomeAborted; delivered as the third parameter of OnCycleEnd (first marking wins; a consumer abandoning the iterator mid-cycle leaves it unmarked until the guarantee defer stamps Aborted)
- `Hooks{BeforeStimulate, AfterStimulate, BeforeThink, AfterThink, BeforeAct, AfterAct, OnError, OnCycleEnd}`: interception points (**all eight required — explicit no-op, not absence; a nil callback fails assembly**); BeforeStimulate fires once before any event with a Prompt prototype — content fields (System/Identity/Methods/Tools/Context/Input/Plan/Reflection) are written back to LoopContext and apply to every round; an error aborts the whole Stimulate; AfterStimulate fires exactly once at cycle end (all paths); AfterAct receives the tool execution error (err non-nil = effector failure); OnCycleEnd receives (ctx, output, outcome CycleOutcome)
- `Sandbox` interface: `Allow(ctx, Action) (Verdict, reason string, err error)` + `Emit(ctx, Utterance) (Verdict, reason string, err error)` + `Bounds() string` — **required membrane; it guards both sides of the loop**: every tool execution passes Allow, every round's text passes Emit via `utter` (before the text event, the accumulated output and the next Think — `Deny` replaces the draft with `[sandbox-denied: reason]` and appends it to the Context track, `Ask` withholds it and suspends with the draft inside the Session) — Deny → `[sandbox-denied: reason]` feedback, loop continues; Allow → execution proceeds; a non-nil err coerces to Deny with reason `sandbox error: <err>` (feedback lands as `[sandbox-denied: sandbox error: ...]`) — and every decision first yields EventSandbox as the audit record; an Ask ruling suspends the loop through the shared emitWait path (Question = the ask reason; audit Reason left empty for the ask record) and Resume resolves it per the response grammar; Bounds snapshotted once per Stimulate before the BeforeStimulate hook and carried read-only on the Prompt prototype (hooks may read it but cannot override it — not written back)
- `ContextBudget{MaxTokens, Trimmer, TrimResults}`: **required regulator, one limit over both accumulating tracks**: before each Think the loop calls `Trimmer` on the text `Context` and `TrimResults` on the structured `ToolResults`, both with `MaxTokens` (the only two inputs that grow within a cycle — every other prompt field is replaced wholesale per round); a nil `Trimmer`, a nil `TrimResults` or MaxTokens <= 0 fails assembly (a budget that does not trim is not a budget, and half a budget is not a budget either)
- `Thinker` / `Effector` / `Closer`: host port interfaces (no stubs — host must provide all)
- `GuardStack(layers ...Sandbox) Sandbox` / `FallbackThinker(ports ...Thinker) Thinker` / `FallbackEffector(ports ...Effector) Effector` (compose.go): combinators that return an existing port type, so the loop cannot tell a composed organ from a plain one and no slot is added. `guardStack.rule` is shared by both membrane sides and applies severity, not layer order: the first Deny (or member error, which the port contract already coerces to Deny) ends the stack, the first Ask is remembered and wins over Allow, an empty stack denies; `Bounds()` is the first non-empty. A fallback port returns the first member whose call has `err == nil` — for the effector that includes a business refusal carried in `Effect.Err`, which is a result, not a broken organ — and joins every member's error when all fail (an empty stack is an error, never a fabricated decision). A combinator never forwards `Boot`: the framework asserts the capability on the port value it is handed, so a member that must come up first is booted by the host before it is composed
- `Bootable{Boot(ctx) error}` (lifecycle.go): an optional capability a host organ may declare; the framework type-asserts it and calls it once per instance. `PortOrder()` derives the sequence to bring ports up from the blueprint itself (required phase-2 wiring points, in `Connectome()` order), so a newly required port cannot be left out of the boot list the way it could be left out of a hand-written one
- `Memory` interface: `Recall(ctx, MemoryQuery{CellID, Cue}) ([]Record, error)` + `Remember(ctx, CycleFacts{CellID, Input, Output, Outcome}) error` — **required port**: the framework owns the two timepoints (recall after the budget trim and before BeforeThink; remember once per invocation at its terminal, before OnCycleEnd, on all four exit arms), the organ owns storage, ranking and retention. A Recall error ends that Think via EventError; a Remember error is reported through OnError and never rewrites the outcome. Records are pure data (Key/CellID/Kind/Content/Created); deletion and forgetting never pass through this port
- `Signal{ID, From, To, Kind, Status, ReplyTo, Skill, Payload}`: inter-individual message carrier; the framework both moves it (colony → cell queue → `Prompt.Stimuli`) and fills it — `Cell.emit` owns `ID`/`From`/`Kind` and the opening task state, the loop owns `ReplyTo`/`Status` on the answer path, so a host never assigns any of those; `To`, `Skill` and `Payload` are what the host names, and what a payload means stays host-level
- `SignalKind`: KindStimulus (a task put to this cell) / KindResponse (an answer, `ReplyTo` names the signal it answers) / KindNotice (side-channel: runs no loop of its own; the framework withholds from the round that drains it exactly one thing — a Payload naming a single tool)
- `TaskStatus`: A2A-style task lifecycle states carried by `Signal.Status`; "" = not tracked. **Exactly one writer per state**: `TaskSubmitted` is stamped by `Cell.emit` on an outbound request, `TaskWorking` by the loop's ingest step on every stimulus it takes from the queue, and the four closing states (`TaskNeedsInput`/`TaskCompleted`/`TaskFailed`/`TaskCancelled`) are all returned by `TaskOutcome(CycleOutcome, ctxErr)` — the way the invocation ended already says how the task it served stands, so no organ reports one
- `TaskOutcome(o CycleOutcome, ctxErr error) TaskStatus`: the single mapping (Done→Completed, Suspended→NeedsInput, Error/MaxRounds→Cancelled if the context was canceled else Failed); an abandoned iterator (`OutcomeAborted`) returns "" and therefore sends no answer at all — work that stopped mid-flight without failing has no lifecycle to report
- `Correlation{SignalID, CellID string, Call ToolCall, Session Session, Status TaskStatus, Response []byte}`: one delegation the kernel is tracking, and after the answer lands one resumption waiting for the host — the kernel pairs request to reply and carries the resume handle, while when (or whether) a suspended round continues stays the host's decision
- `InboxCapacity = 8`: the depth of a cell's inbound queue; a sender that reaches it is refused (`ErrTargetBusy`) rather than blocked

## Key Decisions

- DecisionLoop is pure orchestration — no default Think/Act implementations, no stubs
- Suspension: a tool returning Effect.WaitInput suspends the loop — snapshot a Session (round/Context/ToolResults/remaining calls/output), yield StateWaiting + EventWaitInput, end the iterator normally (no Done/Error); OnCycleEnd/AfterStimulate still fire exactly once (finalOutput "" on the suspension path, like the error path); Resume reloads the session and appends the response as the pending tool's structured result (ID = sess.pending.ID); runs the remaining calls of the suspended round, then re-enters the round loop from the suspended round — the digesting Think uses the suspended round's quota (no extra round); budget trimming runs only before each Think (none during the wait); timeouts are host-controlled (resume with "[denied: timeout]")
- Unified suspension-resume: the pause gate never blocks — a pending pause at a gap point yields StatePaused + EventPaused with a Session snapshot (pending zero value; remaining from the current tool on, since the current tool has not run yet) and ends the iterator normally; Resume(sess, "") continues (nothing is injected — pending.ID == ""); Pause/ask_user now share the same Session/Resume machinery (LangGraph-interrupt-style single suspension primitive); Unpause only clears a pause request that has not taken effect yet
- Tri-state rulings + outcome classification: a VerdictAsk ruling suspends through the same emitWait machinery as a tool WaitInput (the Session records which ask it is; OutcomeSuspended marked) — Resume resolves per the response grammar: "" denies as `[sandbox-denied: declined]`, a `[denied:` prefix lands its text as the deny reason in the canonical `[sandbox-denied: ...]` form, anything else approves; the approved pending call executes WITHOUT consulting the sandbox again (a stateless membrane would re-ask forever), while non-pending siblings replay through the normal gate; finalized denials are excluded from the snapshot tail (their feedback already landed)
- Output membrane: the same port rules the egress side, so no round's text reaches the consumer, the accumulated output or the next Think before the ruling lands; each ruling is audited exactly once and an ask withholds its draft in the Session rather than re-Thinking after approval — the veto belongs to the port, not to a hook (H4 AfterThink stays SemRead)
- Session ownership: the handle names the cell that suspended it and Resume rejects a foreign one, because replaying A's round on B's organs is silent corruption; the wait cause is a name-encoded `waitKind` so an iota reorder cannot reinterpret a saved handle
- Inbound drain: the loop takes from a cell's queue at exactly one point — the Think gap, right after the budget trim and recall — through the injected `Ingest` closure; it never names a channel, because the cell has to route first (a reply that pairs with a delegation belongs to a waiting round, not to this one). `Stimuli` is replaced wholesale per round (a `KindNotice` therefore withholds for precisely the round that drained it, nothing more) and never enters a Session, so whatever arrives during a long Act waits for the next Think rather than being half-applied. Consequences: an in-flight Act is never preempted, and a cell with no colony wiring simply has no inbound track — `Stimuli` stays empty.
- Cross-cell delegation: a tool returns `Effect.Send` instead of calling a synapse it was handed, which is what lets the cell mint the id and keep the pairing — an organ that fires its own signals produces answers nobody can route back. The wait is the existing tool suspension (`waitKind` = tool), so no new wire kind and no second resume path; one delegation per round (a second is refused as tool feedback, never silently dropped), and resistance (no Colony organ, unknown or busy target) never suspends.
- Answer as debt: every `KindStimulus` taken with an `ID` and a `From` is a request expecting a reply, so the invocation carries that list (`Requests`) across rounds and across a suspension inside the Session, and the cycle guarantees discharge it at the terminal — before `Remember` and `OnCycleEnd`, so the memory organ and the hook observe the same answer the requester does. The status comes from `TaskOutcome`, an abandoned iterator sends nothing, and an answer with no way out reaches `OnError` rather than vanishing. Answers go out on `context.WithoutCancel` because the requester's notice is the point of the call.
- Pairing, not resumption: the kernel matches a reply to the round that asked and hands the pair to the host (`Agent.Resumptions`, non-consuming; `Agent.Ack` ends it); it never resumes on its own. Continuing a suspended round is a decision about the host's workload, and a task may report needs-input before completed — consuming the pairing on read would lose the second answer.
- Outcome classification: CycleOutcome (zero value reserved) is delivered by OnCycleEnd(ctx, output, outcome) — Done/Suspended/MaxRounds/Error marked at their branch points first-wins; an unmarked cycle means the consumer abandoned the iterator, stamped OutcomeAborted by the guarantee defer right before the hook fires; hook/event ordering unchanged
- Reflection slot (primitive lite): Prompt.Reflection + LoopContext.Reflection carried verbatim onto every Thinker prompt of the turn — the host writes it on the BeforeStimulate prototype; the loop owns no reflection logic of its own (wiring only, host fills the flesh)
- MaxRounds<=0 uses DefaultMaxRounds=8; round exhaustion with remaining ToolCalls yields ErrMaxRounds via emitError
- ParallelActs batch parallelism (opt-in; parallel.go): runToolCalls diverts to runToolCallsParallel iff ParallelActs && len(calls) > 1 (a single call keeps the serial path). Three phases: (1) serial gating — all EventToolCall announced in call order, one pause gap point for the whole batch (a hit snapshots the whole batch unexecuted — Resume replays it), per-call gateTool (the serial-path-shared membrane gate: EventSandbox verdict + BeforeAct; denied calls get [sandbox-denied: ...] in place and are skipped, siblings unaffected); (2) parallel execution — one goroutine per admitted call runs actWithRetry on the *gated* Action (BeforeAct mutations apply), sync.WaitGroup.Go join, results land by call index (goroutines read lc config/ports read-only; hooks/events/state never enter this phase); (3) serial feedback — toolFeedback (AfterAct → ToolResult → EventToolResult) keyed by the *original* ToolCall (feedback/snapshot identity, identical to the serial path), in call order, never completion order. A WaitInput result (first in call order, wins over err) suspends via the shared emitWait with remaining nil — the batch fully executed, Resume must not replay; every sibling's feedback (before AND after the suspending call) is appended before the snapshot, and a later sibling's own wait is refused (refuseLaterWait) because the batch has no second suspension to spend. MaxParallelActs narrows phase 2 with a bounded slot channel — it changes when a call runs, never which calls run or where their feedback lands, and it binds nothing while ParallelActs is off. Still no ActBatch port, no tool side-effect classification — parallelism eligibility is the model's (batch split) and host's (switch) joint promise
- Event wire: names, not numbers, and never a silent loss (eventwire.go): enums on the stream (`EventKind`, `LoopState`, membrane ruling, suspension flavour) each carry one table of names indexed by value, so an iota reordering must not silently reinterpret a journal written last week — and a value with no name is refused on the way **out** (`EncodeEvent`, `Session.Marshal`) rather than written as a record nothing can read back. What genuinely cannot cross (an error the framework does not own) crosses as text and says so in `Dropped`; `json.Marshal` of `Event` is rejected as the alternative because it writes an `error` field as `{}` — the loss is real and reported nowhere. The `Session` inside a suspension is embedded as its own bytes so the handle's version guard stays the authority.
- An audit record describes, it does not possess: `ReplaceAudit` names the swapped ports by type instead of holding them. It is emitted at a later Stimulate than the swap it records, so holding the value kept a retired organ alive, made the record unserializable, and duplicated what `Replace` already returns to the caller.
- Authorship is the cell's fact: `Event.CellID` is stamped once where events leave the cell, not by each of the many producers inside the loop — a stream that reaches another process has to say who spoke, and one boundary is the only place that can promise it for every event.
- Think retry: MaxRetries attempts, ctx cancellation returns immediately
- Tool execution: actWithRetry applies per-attempt ToolTimeout (<=0 = none) and ToolMaxRetries (<=0 = none) — retry on effector err only (Effect.Err never retried, avoids duplicate side effects); timeout/cancel errors not retried; the final error still flows through ToolResults.Err (resistance is feedback); it is the single Act chokepoint — the nil-effect port-contract guard (success + nil Effect → Effect{Err: "nil effect from effector"}) lives here, both execution paths inherit it
- Error paths are unified through emitError: State(StateError) → EventError → OnError (only on normal delivery); OnCycleEnd is guaranteed exactly once via Cycle defer (normal/error/abort)
- Stimulate boundary hooks: BeforeStimulate/AfterStimulate fire exactly once per Stimulate — BeforeStimulate receives a Prompt prototype (Context is a shallow copy, so in-place edits or an early hook error never leak into lc) and its content fields (incl. Reflection) are written back to LoopContext (one-shot injection applies to all rounds; error terminates via emitError); AfterStimulate runs in a nested defer after OnCycleEnd (normal/error/abort, survives an OnCycleEnd panic). BeforeStimulate runs before the ctx-cancellation check, so it fires exactly once even on a canceled context. Injected Context is subject to Budget.Trimmer like all loop context — hosts should size injections within MaxTokens.
- AfterAct receives the raw tool err (nil on success); tool failure text still flows through ToolResults.Err
- Tool error feedback: Act err/Effect.Err/nil effect populate ToolResults.Err (truncated), loop continues — no text track formatting (rendering is the host's decision)
- Structured tool feedback: tool results enter Prompt.ToolResults as ToolResult{ID: tc.ID, Name: tc.Name, Result/Err: truncated raw output} — the LLM call id is preserved and Context never carries tool results (single track); sandbox denials stay text-only ([sandbox-denied: ...] is a verdict, not a result); Resume appends the external response as the pending tool's entry; Session snapshot carries the accumulated ToolResults; EventToolResult echoes the call (Event.ToolCall) for ID association
- Sandbox ruling before each side takes effect (Allow before a call, Emit before a round's text is heard): three-state routing — Deny → feedback `[sandbox-denied: reason]`, loop continues; Allow → proceed; Ask → suspend-and-confirm through the unified suspension path (EventWaitInput carries Verdict.Question); every decision of the membrane first yields EventSandbox as the audit record (ask chains close with a terminal resolve record) — hosts persist it for the action-level audit trail
- MaxToolOutput truncates ToolResults.Result/Err fields (<=0 = no truncation); truncation keeps UTF-8 rune boundaries
- All errors wrapped with `fmt.Errorf("...: %w", err)`

## Pitfalls

- Host ports must respect ctx: long operations must monitor ctx.Done (otherwise Close cannot interrupt)
- No default organ implementations inside the loop — storage, ranking and retention belong to the host's Memory organ; `LoopContext.Context` carries host text and sandbox denials only, never recalled records (those reach the Thinker on `Prompt.Memories`)
- Hooks/Sandbox/Budget/Mem are required organs: internal tests fill no-op defaults where they do not target these ports; the api assembly (New/Validate) is where requiredness is enforced
- History/context accumulation happens within the loop only (Context grows with sandbox denials; tool feedback accumulates in ToolResults) — BeforeThink shares the backing array with lc.ToolResults too: replace the slice wholesale, never append in place
- Emit/yield returns false to stop early — callers control termination; abort discards the round, tools after the stop point do not execute, OnCycleEnd still runs (defer) — such a cycle reports OutcomeAborted
- StatePaused is produced by the pause gate at gap points (before each Think / tool execution); a pending pause yields EventPaused with a Session snapshot and ends the iterator normally — no blocking, no ctx cancellation, no ResumeCh; Resume(sess, "") continues; a consumer abort before EventPaused stops the round as usual
- StateWaiting is produced by a tool suspension (Effect.WaitInput) — distinct from StatePaused (gap-point pause): the iterator ends normally, the host resumes via Resume(sess, response); Session is single-use and never mutated by the framework; a VerdictAsk sandbox ruling reaches the identical StateWaiting/EventWaitInput pair (question text comes from the ask, not a tool effect) and resolves with the same response grammar (empty / `[denied:` prefix / else approve)
- ParallelActs requires a concurrency-safe Effector (documented on LoopConfig; Validate emits an info finding when enabled); the parallel phase never calls hooks or yields events — a host observing strictly serial hook/event interleaving is unaffected by the switch
- PendingReplace (LoopContext field) is drained by the cell snapshot; the loop emits them before any other event — hosts must not inspect them mid-cycle
- Inbound signals are consumed only at a Think gap (or when the host reads `Resumptions`): an agent nobody Stimulates keeps its whole queue, and the cell stops taking at `InboxCapacity` — leaving a signal in the channel rather than dropping it, so a not-running cell still refuses senders (`ErrTargetBusy`, the synapse never blocks) instead of absorbing the colony in memory. `Prompt.Stimuli` is this round's batch, not a log — a host that wants history keeps its own
- A paired answer stays in `Resumptions()` until the host calls `Ack(signalID)` — reads never consume, so an unacked delegation is reported on every read, and while it is live each further reply for the same request appends another resumption (that is what lets needs-input and completed both reach the host)
