# MeowAgent nerve module context (capability layer: decision loop + ports)

> Package lives at internal/nerve — sealed from external import; hosts use only the api package API.

## Purpose

- Capability layer: decision loop orchestration, host ports (Thinker/Effector/Closer), hooks, events
- File layout by concern: `state.go` (loop states, round cap, LoopConfig), `loop.go` (LoopContext, Cycle/Resume, round loop, Think), `feedback.go` (actBatch — one round's Act path), `gate.go` (membrane ruling, audit, denial), `pause.go` (pause gate + the shared suspension snapshot), `retry.go` (Think/Act retry, truncation), `parallel.go` (opt-in batch path), `hooks.go` (hook adapters + error terminal), plus `port.go`, `event.go`, `signal.go`, `wire.go`
- `size_test.go` enforces the complexity budget mechanically (file ≤400 lines, function body ≤50, ≤4 params) over the whole module; the exemption list is closed and each entry carries its reason
- Guard ports: Sandbox (execution boundary), ContextBudget (context size limit)
- Depends on nothing above cell/synapse/root (memory is standalone, not referenced)

## Dependencies

- Go standard library only (context/fmt/unicode/utf8)

## Interface Contract

- `DecisionLoop{}.Cycle(ctx, *LoopContext, yield)`: pure orchestration — Think → Act → yield events
- `DecisionLoop{}.Resume(ctx, *LoopContext, sess Session, response string, yield)`: continues a suspended loop from a Session (EventWaitInput or EventPaused) — for a tool suspension the response is injected as the pending tool's structured result (pending.ID == "" for pause suspensions: nothing is injected, the loop just continues); a sandbox ask suspension (sess.sandboxAsk, wire v2) resolves on the same channel — an empty or `[denied:`-prefixed response denies the pending call (`""` defaults to the `[sandbox-denied: declined]` feedback, a `[denied:`-prefixed response denies with its text in the canonical `[sandbox-denied: ...]` form — input protocol and output feedback are distinct formats), any other response approves it without re-gating (non-pending siblings still pass the normal gate on replay); remaining tools run, round loop resumes from the suspended round (no extra round, no budget during the wait); stream/hooks/guarantees isomorphic with Cycle
- `LoopState`: StateIdle/StateThinking/StateActing/StatePaused/StateWaiting/StateDone/StateError (StatePaused + EventPaused yielded by the pause gate at gap points, iterator ends normally — resumed via Resume(sess, ""); StateWaiting + EventWaitInput yielded when a tool suspends — resumed via Resume(sess, response))
- `LoopConfig{MaxRounds, MaxToolOutput, MaxRetries, ToolTimeout, ToolMaxRetries, ParallelActs}`: scalar loop config (single source; api.Config aliases it); UpdateConfig swaps it wholesale — next Stimulate/Resume snapshots the new values
- `LoopContext{CellID, Identity string, Methods []MethodSpec, Think, Act, Hooks, Sandbox, Budget, Pause, MaxRounds, MaxToolOutput, MaxRetries, ToolTimeout, ToolMaxRetries, ParallelActs, State, Input, Plan, Context, Bounds, Reflection, ToolResults, PendingReplace, PendingConfig, System, Tools}`: all ports injected via fields; `Reflection` is the turn-scoped self-review note carried onto every Thinker prompt (written back from the BeforeStimulate prototype)
- `PauseGate{IsPaused}`: optional pause gate (nil = unsupported); the loop checks it at gap points (before each Think, before each tool execution) — a pending pause yields EventState(StatePaused) + EventPaused with a Session snapshot and ends the iterator normally (unified suspension-resume path since v1.3.2; no blocking, no ResumeCh)
- `Prompt{System, Identity string, Methods []MethodSpec, Tools, Context, Bounds, Input, Plan, Reflection, ToolResults}`: sole data package delivered to Thinker; Reflection = turn-scoped self-review note (write it on the BeforeStimulate prototype; empty = absent); Context = host-injected base + framework-appended sandbox denials (`[sandbox-denied: ...]`, emitted in final form) — the text track holds only those two; Bounds = Sandbox.Bounds() snapshot taken once per Stimulate; ToolResults = single structured track (ToolResult{ID, Name, Result, Err} — ID echoes the LLM call id, Result/Err carry the truncated raw output, Err non-empty = failed; not trimmed; sandbox denials never appear; rendering is the host's decision)
- `Decision{Text, ToolCalls, Usage}`: Thinker output; non-empty ToolCalls triggers Act phase; Usage (nil = skip) is yielded as EventUsage
- `Action{CellID, Call}` / `Effect{Result, Err, WaitInput}`: tool execution pair; WaitInput non-empty = suspend the loop (request external input; the field is the question text) — the loop yields EventWaitInput and ends the iterator normally, the host resumes via Resume(sess, response); WaitInput wins over err (explicit intent), a nil effect never suspends
- `WaitInput{CellID, Call, Question, Session}`: EventWaitInput/EventPaused payload — the suspending tool (Call zero value for a pause), the question text (empty for a pause), and the resume handle
- `Session` (opaque): snapshot at the suspension point (round/input/plan/context/output/pending/remaining/toolResults — all unexported); produced by the framework, consumed by Resume; hosts only save and pass it back; single-use (resuming twice re-executes remaining tools — host responsibility); valid iff round >= 1 (zero value rejected); `RemainingCalls() []ToolCall` (v1.3.3) is the sole sanctioned read-only probe — a clone of the calls not yet executed at the suspension point (empty when nothing is left to run); persistence round-trip via `Marshal() ([]byte, error)` / `UnmarshalSession([]byte) (Session, error)` (JSON wire shape with version guard — a stale or future handle is rejected; wire v2 carries the `sandboxAsk` discriminator)
- `Identity string`: identity description text, host composed (no structure enforced)
- `MethodSpec{Name, Desc, Input, Output}`: built-in capability description (gene projection, describes only)
- `ToolSpec{Name, Desc, Input, Output}`: host-defined tool specification
- `Usage{Prompt, Completion, Total}`: token accounting; host accumulates via EventUsage events
- `Event{Kind, Text, ToolCall, Effect, State, Err, Output, Usage, Verdict, Wait, Replace, Config}`: typed event from each loop iteration
- `EventKind`: EventText/EventToolCall/EventToolResult/EventState/EventDone/EventError/EventUsage/EventSandbox/EventWaitInput/EventPaused/EventReplace/EventConfig
- `ReplaceAudit{CellID, Slot, Old, New}`: audit record carried by EventReplace — one per successful Replace, emitted at the start of the next Stimulate/Resume (the moment the swap takes effect), before any other event; failed swaps record nothing
- `ConfigAudit{CellID, Old LoopConfig, New LoopConfig}`: audit record carried by EventConfig — one per successful UpdateConfig, emitted at the start of the next Stimulate/Resume after EventReplace (the moment the swap takes effect); the config-update counterpart of EventReplace (every "unique update" of the loop is traceable)
- `Verdict`: tri-state sandbox ruling — VerdictDeny (zero value, fail-closed) / VerdictAllow / VerdictAsk
- `SandboxVerdict{CellID string, Call ToolCall, Ruling Verdict, Reason string, Question string, Err error}`: audit record carried by EventSandbox — one verdict per tool execution (the membrane is required, so every execution is audited); an ask ruling produces two records on one chain (ask → resolve; the terminal record closes it with the final Ruling/Reason — deny keeps the deny text, approval shows Ruling allow with empty Reason)
- `CycleOutcome`: zero-value-reserved classification of how the cycle ended — OutcomeDone / OutcomeSuspended / OutcomeMaxRounds / OutcomeError / OutcomeAborted; delivered as the third parameter of OnCycleEnd (first marking wins; a consumer abandoning the iterator mid-cycle leaves it unmarked until the guarantee defer stamps Aborted)
- `Hooks{BeforeStimulate, AfterStimulate, BeforeThink, AfterThink, BeforeAct, AfterAct, OnError, OnCycleEnd}`: interception points (**all eight required since 1.2.0 — explicit no-op, not absence; a nil callback fails assembly**); BeforeStimulate fires once before any event with a Prompt prototype — content fields (System/Identity/Methods/Tools/Context/Input/Plan/Reflection) are written back to LoopContext and apply to every round; an error aborts the whole Stimulate; AfterStimulate fires exactly once at cycle end (all paths); AfterAct receives the tool execution error (err non-nil = effector failure); OnCycleEnd receives (ctx, output, outcome CycleOutcome)
- `Sandbox` interface: `Allow(ctx, Action) (Verdict, reason string, err error)` + `Bounds() string` — **required membrane (since 1.2.0 the loop never tolerates nil)**: every tool execution passes Allow — Deny → `[sandbox-denied: reason]` feedback, loop continues; Allow → execution proceeds; a non-nil err coerces to Deny with reason `sandbox error: <err>` (feedback lands as `[sandbox-denied: sandbox error: ...]`) — and every decision first yields EventSandbox as the audit record; an Ask ruling suspends the loop through the shared emitWait path (Question = the ask reason; audit Reason left empty for the ask record) and Resume resolves it per the response grammar; Bounds snapshotted once per Stimulate before the BeforeStimulate hook and carried read-only on the Prompt prototype (hooks may read it but cannot override it — not written back)
- `ContextBudget{MaxTokens, Trimmer, TrimResults}`: **required regulator, one limit over both accumulating tracks**: before each Think the loop calls `Trimmer` on the text `Context` and `TrimResults` on the structured `ToolResults`, both with `MaxTokens` (the only two inputs that grow within a cycle — every other prompt field is replaced wholesale per round); a nil `Trimmer`, a nil `TrimResults` or MaxTokens <= 0 fails assembly (a budget that does not trim is not a budget, and half a budget is not a budget either)
- `Thinker` / `Effector` / `Closer`: host port interfaces (no stubs — host must provide all)
- `Signal{ID, From, To, Kind, Status, Payload}`: inter-individual message carrier (host-level type, framework does not consume)
- `SignalKind`: KindStimulus/KindResponse/KindNotice (host-side routing semantics)
- `TaskStatus`: A2A-style task lifecycle states (TaskSubmitted/TaskWorking/TaskNeedsInput/TaskCompleted/TaskFailed/TaskCancelled) carried by `Signal.Status`; "" = not tracked

## Key Decisions

- DecisionLoop is pure orchestration — no default Think/Act implementations, no stubs
- Suspension (v1.3.0): a tool returning Effect.WaitInput suspends the loop — snapshot a Session (round/Context/ToolResults/remaining calls/output), yield StateWaiting + EventWaitInput, end the iterator normally (no Done/Error); OnCycleEnd/AfterStimulate still fire exactly once (finalOutput "" on the suspension path, like the error path); Resume reloads the session and appends the response as the pending tool's structured result (ID = sess.pending.ID); runs the remaining calls of the suspended round, then re-enters the round loop from the suspended round — the digesting Think uses the suspended round's quota (no extra round); budget trimming runs only before each Think (none during the wait); timeouts are host-controlled (resume with "[denied: timeout]")
- Unified suspension-resume (v1.3.2): the pause gate is no longer a blocking wait — a pending pause at a gap point yields StatePaused + EventPaused with a Session snapshot (pending zero value; remaining from the current tool on, since the current tool has not run yet) and ends the iterator normally; Resume(sess, "") continues (nothing is injected — pending.ID == ""); Pause/ask_user now share the same Session/Resume machinery (LangGraph-interrupt-style single suspension primitive); Unpause only clears a pause request that has not taken effect yet
- Tri-state rulings + outcome classification (v1.3.6): a VerdictAsk ruling suspends through the same emitWait machinery as a tool WaitInput (the Session records the sandboxAsk discriminator, wire v2; OutcomeSuspended marked) — Resume resolves per the response grammar: "" denies as `[sandbox-denied: declined]`, a `[denied:` prefix lands its text as the deny reason in the canonical `[sandbox-denied: ...]` form, anything else approves; the approved pending call executes WITHOUT consulting the sandbox again (a stateless membrane would re-ask forever), while non-pending siblings replay through the normal gate; finalized denials are excluded from the snapshot tail (their feedback already landed)
- Outcome classification (v1.3.6): CycleOutcome (zero value reserved) is delivered by OnCycleEnd(ctx, output, outcome) — Done/Suspended/MaxRounds/Error marked at their branch points first-wins; an unmarked cycle means the consumer abandoned the iterator, stamped OutcomeAborted by the guarantee defer right before the hook fires; hook/event ordering unchanged
- Reflection slot (v1.3.6, primitive lite): Prompt.Reflection + LoopContext.Reflection carried verbatim onto every Thinker prompt of the turn — the host writes it on the BeforeStimulate prototype; the loop owns no reflection logic of its own (wiring only, host fills the flesh)
- MaxRounds<=0 uses DefaultMaxRounds=8; round exhaustion with remaining ToolCalls yields ErrMaxRounds via emitError
- ParallelActs batch parallelism (v1.3.3, opt-in; parallel.go): runToolCalls diverts to runToolCallsParallel iff ParallelActs && len(calls) > 1 (a single call keeps the serial path). Three phases: (1) serial gating — all EventToolCall announced in call order, one pause gap point for the whole batch (a hit snapshots the whole batch unexecuted — Resume replays it), per-call gateTool (the serial-path-shared membrane gate: EventSandbox verdict + BeforeAct; denied calls get [sandbox-denied: ...] in place and are skipped, siblings unaffected); (2) parallel execution — one goroutine per admitted call runs actWithRetry on the *gated* Action (BeforeAct mutations apply — v1.3.5 parity fix), sync.WaitGroup.Go join, results land by call index (goroutines read lc config/ports read-only; hooks/events/state never enter this phase); (3) serial feedback — toolFeedback (AfterAct → ToolResult → EventToolResult) keyed by the *original* ToolCall (feedback/snapshot identity, identical to the serial path), in call order, never completion order. A WaitInput result (first in call order, wins over err) suspends via the shared emitWait with remaining nil — the batch fully executed, Resume must not replay; every sibling's feedback (before AND after the suspending call) is appended before the snapshot. No batch throttling (MaxParallelActs), no ActBatch port, no tool side-effect classification — parallelism eligibility is the model's (batch split) and host's (switch) joint promise
- Think retry: MaxRetries attempts, ctx cancellation returns immediately
- Tool execution: actWithRetry applies per-attempt ToolTimeout (<=0 = none) and ToolMaxRetries (<=0 = none) — retry on effector err only (Effect.Err never retried, avoids duplicate side effects); timeout/cancel errors not retried; the final error still flows through ToolResults.Err (resistance is feedback); it is the single Act chokepoint — the nil-effect port-contract guard (success + nil Effect → Effect{Err: "nil effect from effector"}) lives here, both execution paths inherit it
- Error paths are unified through emitError: State(StateError) → EventError → OnError (only on normal delivery); OnCycleEnd is guaranteed exactly once via Cycle defer (normal/error/abort)
- Stimulate boundary hooks: BeforeStimulate/AfterStimulate fire exactly once per Stimulate — BeforeStimulate receives a Prompt prototype (Context is a shallow copy, so in-place edits or an early hook error never leak into lc) and its content fields (incl. Reflection) are written back to LoopContext (one-shot injection applies to all rounds; error terminates via emitError); AfterStimulate runs in a nested defer after OnCycleEnd (normal/error/abort, survives an OnCycleEnd panic). BeforeStimulate runs before the ctx-cancellation check, so it fires exactly once even on a canceled context. Injected Context is subject to Budget.Trimmer like all loop context — hosts should size injections within MaxTokens.
- AfterAct receives the raw tool err (nil on success); tool failure text still flows through ToolResults.Err
- Tool error feedback: Act err/Effect.Err/nil effect populate ToolResults.Err (truncated), loop continues — no text track formatting since v1.3.1 (rendering is the host's decision)
- Structured tool feedback (v1.3.1): tool results enter Prompt.ToolResults as ToolResult{ID: tc.ID, Name: tc.Name, Result/Err: truncated raw output} — the LLM call id is preserved (was dropped) and Context no longer carries tool results (single track); sandbox denials stay text-only ([sandbox-denied: ...] is a verdict, not a result); Resume appends the external response as the pending tool's entry; Session snapshot carries the accumulated ToolResults; EventToolResult echoes the call (Event.ToolCall) for ID association
- Sandbox check before each tool execution: three-state routing — Deny → feedback `[sandbox-denied: reason]`, loop continues; Allow → proceed; Ask → suspend-and-confirm through the unified suspension path (EventWaitInput carries Verdict.Question); every decision of the membrane first yields EventSandbox as the audit record (ask chains close with a terminal resolve record) — hosts persist it for the action-level audit trail
- MaxToolOutput truncates ToolResults.Result/Err fields (<=0 = no truncation); truncation keeps UTF-8 rune boundaries
- All errors wrapped with `fmt.Errorf("...: %w", err)`

## Pitfalls

- Host ports must respect ctx: long operations must monitor ctx.Done (otherwise Close cannot interrupt)
- No default Memory/LLM implementations inside the loop — memory is host-managed via LoopContext.Context
- Hooks/Sandbox/Budget are required organs: internal tests fill no-op defaults where they do not target these ports; the api assembly (New/Validate) is where requiredness is enforced
- History/context accumulation happens within the loop only (Context grows with sandbox denials; tool feedback accumulates in ToolResults) — BeforeThink shares the backing array with lc.ToolResults too: replace the slice wholesale, never append in place
- Emit/yield returns false to stop early — callers control termination; abort discards the round, tools after the stop point do not execute, OnCycleEnd still runs (defer) — such a cycle reports OutcomeAborted
- StatePaused is produced by the pause gate at gap points (before each Think / tool execution); a pending pause yields EventPaused with a Session snapshot and ends the iterator normally — no blocking, no ctx cancellation, no ResumeCh; Resume(sess, "") continues; a consumer abort before EventPaused stops the round as usual
- StateWaiting is produced by a tool suspension (Effect.WaitInput) — distinct from StatePaused (gap-point pause): the iterator ends normally, the host resumes via Resume(sess, response); Session is single-use and never mutated by the framework; a VerdictAsk sandbox ruling reaches the identical StateWaiting/EventWaitInput pair (question text comes from the ask, not a tool effect) and resolves with the same response grammar (empty / `[denied:` prefix / else approve)
- ParallelActs requires a concurrency-safe Effector (documented on LoopConfig; Validate emits an info finding when enabled); the parallel phase never calls hooks or yields events — a host observing strictly serial hook/event interleaving is unaffected by the switch
- PendingReplace (LoopContext field) is drained by the cell snapshot; the loop emits them before any other event — hosts must not inspect them mid-cycle
